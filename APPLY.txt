xDBML 0.6.7 -- quoted names in every name position, diagnostics copy
Base: origin/main dc273bc (release 0.6.6). Built 2026-10-10.
Edited in place in the clone: there is no archive to unzip.

WHAT IT DOES
------------
  1. Quoted names everywhere a name stands (3.2). @xdbml/parse read a
     quoted identifier only as the name of a declaration and after a dot
     in a path. It now reads one at the head of a path (constraints key
     lines, indexes, both ends of a Ref, inline or long), in the fields of
     a composite Ref, in each segment of a dotted entity, Enum or type
     name, as a TableGroup member, in a top-level records declaration and
     its columns, after ~, in an import path and alias, in a tuple element
     or polymorphic alternative, and as the name of a Ref. The reported
     playground link (constraints { ("Work Order ID", "Part ID") [pk] })
     now parses clean. Checked against @dbml/core 3.13.6: every form DBML
     accepts now parses; ~"name" is the one form xDBML accepts and DBML
     rejects.
  2. A dot inside quotes is part of the name. "my.table" is one entity;
     my.table is entity table of Container my; a document may declare
     both. The AST holds a qualified name with each segment that holds a
     dot or a double quote written in quotes, as in the source; any other
     name reads exactly as before. New file parser/src/names.ts defines the
     form; @xdbml/parse exports joinName, splitName, quoteNameSegment,
     nameQualifier, lastNameSegment and isQualifiedName.
  3. Playground diagnostics panel: text can be selected and copied with
     Ctrl/Cmd+C (a click that ends a selection no longer jumps to the
     source, which took the focus to the editor and lost the selection),
     and a Copy button in the header copies every diagnostic, one per line.
  4. SUPPORTED_XDBML_VERSION = '0.6.7'; CHANGELOG section v0.6.7.

ONE POINT LEFT FOR YOU
----------------------
  20.1 writes a map key as .["literal_key"] (example flags.["dark_mode"]),
  while the grammar and the parser read single quotes, .['dark_mode'];
  the double-quoted form fails with "Unexpected token inside path
  bracket". Unchanged in this delivery.

HOW TO RELEASE
--------------
From cmd.exe at the repo root (C:\Repos\Hackolade\xdbml-spec):

    apply.cmd

apply.cmd runs the gate (npm run check, mcp type-check) and prints:

    git add -A
    git commit -m "0.6.7: quoted names in every name position, diagnostics copy"
    tools\release-preflight.cmd 0.6.7
    tools\release.cmd 0.6.7

git add -A is safe here: the only untracked file is parser\src\names.ts,
which belongs to the delivery. release.cmd publishes @xdbml/parse then
@xdbml/render at 0.6.7 (the renderer imports the new name helpers, and
release.cmd repoints its @xdbml/parse range before building), deploys the
MCP server and the rendering API, commits the version bumps as "release
0.6.7", pushes main, and publishes the GitHub release from the v0.6.7
section of the CHANGELOG.
