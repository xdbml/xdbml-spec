xDBML -- site: Specification menu with superseded versions folded
Base: origin/main 99f43e0 (release 0.6.2). Independent of the 0.6.3
deltas: it touches neither the spec nor any package, so it applies before
or after "0.6.3, delta 1" and needs no version number.

WHAT CHANGED
------------
.vitepress\config.ts
  One version list, read from spec\ the way prepare-spec.mjs finds the
  newest file (vN.M.md and vN.M.P.md, numeric sort). The newest is the
  current draft; the others are superseded. Publishing v0.7 needs no edit
  here: adding spec\v0.7.md moves v0.6 into the superseded group.
  Top-bar "Specification" dropdown: Current draft (v0.6), All versions,
  Grammar. A VitePress dropdown cannot fold a sub-list, so the superseded
  versions leave it; the All versions page and the sidebar keep them.
  Sidebar of /spec/ and /grammar/ pages (one shared group instead of two
  copies): All versions, Current draft, v0.6, then "Superseded versions"
  as a collapsed group holding v0.5 to v0.1, without the "(superseded)"
  suffix. On a superseded page the group opens by itself (VitePress
  useSidebarControl expands a collapsed group holding the active link).
scripts\prepare-spec.mjs
  Header comment: the menu no longer needs a hand edit; only the version
  table in spec\index.md does.
