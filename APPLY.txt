xDBML -- resolver: target-native type names pass through
Base: origin/main 81125b5 (positioning update: Apache Ossie and LinkML).

WHAT CHANGED
------------
The name resolver reported `unresolved-type` for every scalar type name
missing from SCALAR_TYPES / BSON_TYPES in keywords.ts. Those lists exist for
syntax coloring (their own comment says so), and spec §1.2 principle 4 makes
scalar type names pass through as written. Oracle `number`, `clob`, `raw`,
PostgreSQL `serial`, `bytea`, SQL Server `uniqueidentifier`, and fields typed
by a declared DBML `Enum` all failed. F1Data_Tables.xdbml gave 64 errors;
it now gives none. The §27.16 spec example with `number(10)` is clean too.

parser\src\name-resolver.ts
  - A scalar type name that is not a builtin and not a declared Type or
    Enum is a target-native type: no diagnostic.
  - New warning `possible-type-typo` when such a name is a near miss of a
    declared Type or Enum, compared case-insensitively: a case difference
    alone for names of 3 characters or fewer, 1 edit up to 7 characters,
    2 edits from 8 (adjacent transposition = 1 edit). The message names
    the declaration: "did you mean 'Address'?".
  - A field typed by a declared Enum resolves (it used to raise
    `unresolved-type`). An Enum declared in two containers resolves by its
    bare name without a warning.
  - dereferenceNamedType(): a target-native or Enum-typed field is an
    opaque scalar, so a Ref path navigating into it reports
    `invalid-nested-path`, like a path into `varchar`. Before, the walker
    bailed silently and relied on the field-level error.
  - `unresolved-type` stays in DiagnosticCode (NamedTypeReference nodes
    still use it); the field-type pass no longer emits it for a scalar.
parser\test\run-tests.ts
  - P6 "unresolved named type produces unresolved-type diagnostic" is
    replaced by a near-miss case (`Adress` vs `Type Address`) and a
    pass-through case (`NoSuchType` with nothing close: clean).
  - New: 18 fields typed with target-native names (Oracle, PostgreSQL,
    SQL Server, Snowflake, BigQuery, a quoted multi-word type), including
    union/array/map positions; DBML Enum-typed field; Enum in two containers; near-miss
    rules (case only, transposition, array element, union member, nested
    object field, Enum, length thresholds, far names stay silent); paths
    into a native and an Enum-typed field.
