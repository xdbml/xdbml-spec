WHAT CHANGED
------------
Oracle `number`, PostgreSQL `serial`, SQL Server `uniqueidentifier` and
similar names now color as types in the playground editor, the site's code
blocks, and the VS Code extension grammar.

parser\src\keywords.ts
  - NEW `TARGET_NATIVE_TYPES`: 72 names (Oracle, PostgreSQL, SQL Server,
    Snowflake, BigQuery, Cassandra, Protobuf, ClickHouse, plus geometry,
    geography, interval). Highlighting only.
  - Kept out of SCALAR_TYPES on purpose: SCALAR_TYPES/BSON_TYPES are the
    built-in names that a Named Type cannot shadow (spec §15.2), and both
    the name resolver and the module resolver read them. Putting
    `geography` there would stop `Type Geography { ... }` from resolving.
    The comment above SCALAR_TYPES now says so.
  - Left out: generic words that often name fields (point, line, box,
    path, circle, image, counter, duration, name), since coloring does not
    depend on position. Kept, like the existing date/time/year: number,
    raw, interval, bytes, vector.
parser\src\monarch.ts
  `nativeTypes` group, colored `type`.
tools\textmate\xdbml.tmLanguage.template.json, scripts\build.mjs
  `native-types` pattern (scope storage.type.xdbml) filled from
  __TARGET_NATIVE_TYPES__, included next to bson-types in both places.
tools\textmate\xdbml.tmLanguage.json
  Regenerated with build.mjs (nothing to run on your side).
tools\vscode-extension\syntaxes\xdbml.tmLanguage.json
  Synced with scripts\prepare.mjs. The .vsix is NOT rebuilt and the
  extension version is NOT bumped: a release decision.
tools\textmate\scripts\test.mjs
  Targeted check: number, CLOB, serial, uniqueidentifier are
  storage.type.xdbml; point is not. Fails against the old grammar.
tools\textmate\README.md
  "Adding a keyword" says which list a target-native name goes in.
parser\test\run-tests.ts
  4 keyword-consistency tests: all 72 parse as ScalarType and resolve
  clean; no duplicate and no overlap with any other keyword array; Monarch
  carries the list; `Type Geography` still resolves through a Ref path.
