xDBML -- 0.6.5, delta 3: renderer, playground and example 17 (internal definitions)
Base: origin/main 9bc0bb0 (0.6.5, delta 2: grammar and parser). Built 2026-10-03.

A field typed by an internal definition (spec 15.8) now expands in the
diagram and resolves in the inspector, with the scoping of 15.8.2. The
entity inspector lists an entity's internal definitions. Example 17 shows
the construct across JSON Schema, MongoDB and Oracle, and the 15.8.1 spec
example gets its "View in playground" button.

HOW TO APPLY
------------
Extract this folder anywhere outside the repo and run, from cmd.exe in it:

    apply.cmd                      (repo at C:\Repos\Hackolade\xdbml-spec)
    apply.cmd D:\path\to\xdbml-spec

apply.cmd checks that 9bc0bb0 is in the history of HEAD, that the fourteen
edited files are unchanged since 9bc0bb0 and that the two new files do not
exist yet, copies the sixteen files, and runs the gate (npm run check,
then mcp type-check). It stops at the first failure and does not commit.
When it ends green it prints the git commands to commit and push. No
package or lockfile changes, so no npm install.

WHAT CHANGED
------------
renderer\src\layout\layout.ts
  buildEntityLayout resolves type names in the entity's scope: its
  internal definitions over the project's Types (entityDefinitions from
  @xdbml/parse). An expansion that enters a project Type switches to the
  project's Types for that body. The recursion guard tracks
  TypeDeclaration objects instead of names, since an internal definition
  and a project Type may share a name.
playground\src\components\inspector\ast-lookup.ts
  resolveField walks a field path with the same scoping (TypeScopes).
playground\src\components\inspector\EntityInspector.vue
  "Internal definitions" section, after Constraints: each entry with the
  field count of the object form or the base type of the scalar form.
playground\help\diagnostics-panel.md, nested-fields.md, inspector-pane.md
  The five 15.8.6 codes; an "Internal definitions" section under Named
  types; the new inspector section.
examples\17-internal-definitions.xdbml (NEW)
  Claims intake of an insurer. JSON Schema Container `intake`:
  claim_submission declares Address, Party, two incident shapes used as
  oneOf alternatives, Attachment and two scalar definitions with patterns;
  adjuster_note declares a recursive Comment. MongoDB Container
  `operations`: the claims collection declares its own Address, shaped
  differently, with no collision. Oracle Container `finance`: payments
  reuses the Project-level Type MonetaryAmount. No diagnostic.
scripts\examples-manifest.mjs, examples\README.md
  Entry 17; the README table row is generated by the docs build.
renderer\test\goldens\17-internal-definitions.svg (NEW)
  Golden written by the renderer suite.
renderer\test\run-tests.ts, playground\test\run-tests.ts
  Renderer: expansion, project-Type scope past an entry of the same name,
  recursion, invisibility in another entity, well-formed SVG. Playground:
  inspector resolution and scope; example 17 rows and inspector.
spec\v0.6.md
