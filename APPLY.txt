PART 1 -- apply Delta 10 and commit (about 5 minutes)
=============================================================================

What Delta 10 changes
  scripts\spec-playground-links.mjs
      Arguments that are not .md files are now ignored, with a warning.
      Cause of the error you saw: something ran
          npm test # Runs parser + playground tests, ~3 seconds
      cmd.exe does not treat # as a comment, and npm hands any extra
      arguments of `npm test` to the LAST script in its chain. That used to
      be check:vsix, which ignores arguments; since Delta 7 it is
      check:spec-links, which read "#" as a file name. Reproduced here and
      fixed; the same line now prints "ignoring 8 argument(s)" and passes.
  CHANGELOG.md
      v0.5 "Released: 2026-09-21". If you release on another day, change
      that one date before the Part 1 commit; nothing else depends on it.
      The spec-links entry mentions the argument handling.

PART 2 -- release 0.5.0 (about 15 minutes)
=============================================================================

Step 2.1 -- preflight (changes nothing)

  cd /d C:\Repos\Hackolade\xdbml-spec
  tools\release-preflight.cmd 0.5.0

  Expected last line: "Preflight clean. Run:  tools\release.cmd 0.5.0"
  If it reports a problem, fix it with the command the script prints, then
  rerun the preflight. The usual ones:
    [FAIL] not logged in to npm        ->  npm login
    [FAIL] wrangler is not authenticated
                                       ->  cd mcp && npm install --include=dev && npx wrangler login && cd ..
    [FAIL] NODE_ENV=production         ->  set NODE_ENV=
  A [WARN] about uncommitted changes means Step 1.2 was skipped.

Step 2.2 -- publish and deploy

  tools\release.cmd 0.5.0

  What it does, in order, stopping at the first failure:
    [1/5] @xdbml/parse 0.5.0: version, install, tests, npm publish, then
          waits until the registry serves it
    [2/5] @xdbml/render 0.5.0: version, dependency @xdbml/parse ^0.5.0,
          install, tests, npm publish (the publish builds with tsc), waits
    [3/5] MCP server: dependencies ^0.5.0, version 0.5.0, reference check,
          type-check, tests, wrangler deploy
    [4/5] rendering API: dependency @xdbml/render ^0.5.0, type-check,
          wrangler deploy
    [5/5] prints what npm now serves
  Expected end: "Done. Every version and lockfile changed on disk."

  If it fails: read the message, fix, and rerun `tools\release.cmd 0.5.0`.
  Completed steps are safe to repeat, except an npm publish that already
  went through: npm then says "cannot publish over", and you continue from
  the next step by hand, running the commands of that step shown above in
  the corresponding folder.

Step 2.3 -- commit the version bumps and push

  git add -A
  git commit -m "release 0.5.0"
  git push

  The push carries all the local v0.5 commits. On main, the "Build and
  deploy site" workflow publishes the site: /spec/current becomes v0.5,
  the Learn menu gains "Playground help", and the playground ships
  supertype groups. CI runs the full suite on Node 22 and 24.

Step 2.4 -- tag and GitHub release

  tools\github-release.cmd 0.5

  It generates the notes from the CHANGELOG v0.5 section, checks that the
  tree is clean and that local HEAD matches origin/main, then creates tag
  v0.5 and the release. It needs the GitHub CLI (`gh auth login` once); if
  gh is missing, it writes RELEASE-NOTES-v0.5.md and prints the exact manual
  steps instead.
