xDBML -- 0.6.3, delta 4: rendering API, MCP server, llms.txt, VS Code 0.6.3
Base: 0.6.3 delta 3 (renderer, playground and example 16).

Every tool that reads xDBML now handles diagram views. The rendering API
and the MCP server build from the published packages, so their new
parameters go live with the 0.6.3 release (tools\release.cmd 0.6.3), which
publishes @xdbml/parse and @xdbml/render 0.6.3 before installing them in
mcp\ and api\. Until then, their type-checks fail against the published
0.6.2 packages, as expected; here they were checked against the sources.

WHAT CHANGED
------------
api\src\worker.ts, api\README.md
  diagram_view (query) and diagramView (JSON body) render one diagram view.
  An undeclared name returns 400 with the names the document declares; a
  document with none says so. Tester page: a "Diagram view" field.
  /health lists the option.
renderer\src\index.ts, renderer\README.md, renderer\test\run-tests.ts
  diagramViewNames(input): the names a document declares, in order. The
  API uses it to refuse an unknown name without depending on the parser,
  so release.cmd needs no change. One test.
mcp\src\render-tool.ts, mcp\src\index.ts, mcp\README.md
  render_xdbml(..., diagram_view?): renders one diagram view; an undeclared
  name is an error listing the declared ones; the summary names the
  diagram view. Tool description and landing text updated. The README
  also lists the existing mode parameter.
mcp\src\validate-tool.ts
  The summary counts diagram views ("3 entities, 2 containers and 2
  diagram views"), unchanged for a document without any; the outcome and
  the JSON tail carry their names (diagramViews).
mcp\test\parser-from-source*.mjs, mcp\test\run-tests.ts
  The test hook also loads @xdbml/render from source. Five tests: the
  validate summary and JSON tail, an unresolved name, render of a diagram
  view, an undeclared name with and without diagram views, and the full
  diagram without the parameter.
public\llms.txt, mcp\src\reference.ts (regenerated)
  "Diagram views" section after "Supertype groups", with a checked
  example and the narrowing rule; a DiagramView row in "What goes where";
  a Common mistake (an Edges category, parse-error) with its Right form;
  DiagramView among the top-level declarations of checklist item 6.
tools\textmate\xdbml.tmLanguage.template.json, scripts\build.mjs,
scripts\test.mjs, xdbml.tmLanguage.json (rebuilt)
  diagram-view-categories rule: the seven category keywords before '{',
  scope keyword.declaration.category.xdbml. Six smoke checks. The site's
  code blocks use this grammar too.
tools\vscode-extension\package.json, package-lock.json, CHANGELOG.md,
README.md, syntaxes\xdbml.tmLanguage.json (synced),
xdbml-0.6.3.vsix (NEW)
  Version 0.6.3, following the spec point release; 0.6.2 is skipped,
  since that release changed no highlighting.
CHANGELOG.md
  v0.6.3 Tooling: rendering API, MCP server and llms.txt, VS Code and site
  highlighting; diagramViewNames in the renderer entry.
