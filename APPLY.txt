HOW TO APPLY
------------
Unzip the archive at the root of the clone (C:\Repos\Hackolade\xdbml-spec),
then, from cmd.exe at the repo root:

    apply.cmd

apply.cmd copies nothing. It checks that e624f51 is in the history of HEAD
and that no commit since then touched the delivery's files; that each
unzipped file holds this delivery's content; and that the working tree
holds no uncommitted change outside the delivery. It then runs the gate
(npm run check, mcp type-check) and prints the commands below. It does
not commit, publish or deploy.

RELEASE, in order, from the repo root
-------------------------------------
1. Commit and push the delivery (apply.cmd prints the commands).

2. tools\release-preflight.cmd 0.6.5
   Expect every check to pass. 0.6.5 is not on npm for @xdbml/parse or
   @xdbml/render.

3. tools\release.cmd 0.6.5
   Publishes @xdbml/parse 0.6.5 first, then @xdbml/render 0.6.5 against
   it, deploys the MCP server and the rendering API, commits "release
   0.6.5", tags v0.6.5 and creates the GitHub release with notes from the
   v0.6.5 section of CHANGELOG.md. If it stops anywhere, run the same
   command again: nothing is published twice.
   The renderer imports entityDefinitions, new in the 0.6.5 parser, so
   its build must run against @xdbml/parse 0.6.5. release.cmd sets that
   dependency before building. Rehearsed here: parser built from source,
   renderer built against that build (tsc -p tsconfig.build.json, exit
   0), API type-check against the resulting renderer\dist (exit 0).

4. VS Code extension 0.6.5 (tools\vscode-extension\PUBLISH.txt)
     cd tools\vscode-extension
     npx @vscode/vsce publish
   or upload tools\vscode-extension\xdbml-0.6.5.vsix at
   https://marketplace.visualstudio.com/manage/publishers/xdbml
