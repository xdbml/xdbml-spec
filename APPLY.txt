xDBML -- 0.6.3 release, fix 2: wait for the tarball, retry installs for longer
Base: your local main after the second interrupted run of
tools\release.cmd 0.6.3 (release-fix 1 committed; the run stopped in
renderer\ while npm install kept getting a 404 on parse-0.6.3.tgz).

WHAT HAPPENED
  npm serves a new version in pieces. At [1/6], npm view already answered
  for @xdbml/parse 0.6.3 (the registry dates it 15:49:59 UTC), so the
  script went on; at [2/6], npm install still got a 404 on the tarball
  itself, for the 3 minutes the old retry allowed. Checked from here at
  16:02 UTC: metadata and tarball are both served now (HTTP 200).

WHAT CHANGED
------------
tools\release.cmd
  - One wait, used after every publish and whenever a package is found
    already published: it ends only when npm view answers AND a plain
    download of the tarball succeeds (curl, HTTP 2xx), up to 45 minutes,
    with a line each minute saying which of the two is still missing.
  - One install routine for parser, renderer, mcp and api: npm install
    retried every 10 seconds for up to 15 minutes (was 3), numbered tries.
  - The publish markers in %TEMP% stay: nothing is ever published twice.
  - A guard at the start: curl must be on the PATH (it ships with
    Windows 10 and later).
  - Every failure now ends with the same instruction: rerun the same
    command.
tools\release-preflight.cmd
  Checks that curl is present.
tools\RELEASE.md
  How npm serves a version in pieces, and how the script copes.
