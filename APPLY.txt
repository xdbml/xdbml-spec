xDBML -- 0.6.3, delta 2: grammar and parser (diagram views)
Base: origin/main ce1294f (site: Specification menu), with 0.6.3 delta 1
(b4a290c) in it.

The parser now reads DiagramView as Chapter 18 defines it. The renderer and
playground ignore the new declaration until delta 3, so a document with a
diagram view still draws its full diagram. Commit locally and do NOT push
until delta 3: the deployed playground would accept diagram views it cannot
show yet.

WHAT CHANGED
------------
parser\src\ast.ts
  DiagramViewDeclaration (name, wildcardBody, categories), DiagramViewCategory
  (canonical category, keyword as written, wildcard, items) and
  DiagramViewItem (name as written, span). Joins TopLevelStatement.
parser\src\parser.ts
  parseDiagramView at the top level, in every document. Category keywords
  are case-insensitive; Schemas reads as Containers; lists follow 3.9.
  Parse errors, each citing 18.1: an Edges category, an unknown category,
  a body-level * with anything beside it, a DiagramView in a Container, a
  diagramview import in a Container body. SUPPORTED_XDBML_VERSION 0.6.3.
parser\src\diagram-views.ts  (NEW)
  diagramViews(doc), diagramViewMembers(doc, name), checkDiagramViews(doc).
  Members follow 18.2: Tables and Views first; each listed Container adds
  its entities unless Tables names one of them, and its database views
  unless Views names one of them; TableGroups and SupertypeGroups add all
  their members. Frames follow 18.4. Names follow 18.3: qualified id;
  else the element outside any Container; else the one inside a Container;
  an alias under Tables. Table core.users belongs to the implicit Container
  core.
parser\src\name-resolver.ts
  Pass 7 runs checkDiagramViews. New codes: unresolved-diagram-view-name,
  ambiguous-diagram-view-name, diagram-view-wrong-category,
  duplicate-diagram-view, duplicate-diagram-view-category (warning without
  a version declaration, where the lists combine). Extension categories
  without a version declaration reuse construct-requires-version.
parser\src\module-resolver.ts
  reuse { diagramview X } finds the DiagramView X (it found a database view
  of that name); applyAlias covers DiagramView; flatten() moves a
  DiagramView that a container-level reuse * cloned into a Container body
  out to the top level.
parser\src\keywords.ts, parser\src\monarch.ts
  DIAGRAM_VIEW_CATEGORIES; Monaco colors them as declarations before '{'
  only, so an entity or field named tables or notes keeps its color.
parser\src\index.ts, parser\README.md
  Exports and a short README section for the diagram view helpers.
parser\test\run-tests.ts
  New "v0.6.3 diagram views" group, 20 checks. The version-refusal case
  moves from 0.6.3 to 0.6.4.
grammar\xDBML.g4
  diagramViewDefinition, diagramViewCategory, diagramViewCategoryKeyword,
  diagramViewItem, diagramViewName and the DIAGRAM_VIEW token. The rule
  was referenced but never defined; no upstream DBML 3.13.6 rule exists.
grammar\test-cases.md
  Twelve v0.6.3 cases.
CHANGELOG.md
  v0.6.3: Tooling entries for the parser and the grammar.

DECISIONS APPLIED (from the delta 1 review and the follow-up)
  Unknown category and DiagramView in a Container: parse errors. Every
  other 18.6 condition: a diagnostic, so the rest still parses and draws.
