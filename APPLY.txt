xDBML -- 0.6.3, delta 5: diagram view notes, and the diagram in the inspector
Base: origin/main c007ce7 (0.6.3, delta 4).

Two changes agreed after testing delta 3. A diagram view now takes a note,
in its brackets or its body, and custom properties (spec 18.1). And a click
on an empty area of the canvas selects the diagram on display, so the
inspector shows the Project and its note on Main ERD, or the diagram view
and its note.

WHAT CHANGED
------------
spec\v0.6.md
  18.1  The example gains a body Note. New paragraph: a note in the
        brackets or in the body, as for a TableGroup; the body note wins
        when both are written; the brackets also take custom properties
        and no other setting; both are xDBML extensions.
  18.5  A note and the settings brackets need a version declaration.
  18.6  New row: a setting other than note or a custom property. The
        version row adds a note or settings.
  19    DiagramView joins the constructs with inline notes.
  28    Tree: DiagramView gains settings and Note; 28.8 mentions both.
grammar\xDBML.g4, grammar\test-cases.md
  diagramViewDefinition takes settingsBlock? and diagramViewBodyItem
  (category, noteDefinition, or STAR). Three new cases (15 in all).
parser\src\ast.ts, parser.ts
  DiagramViewDeclaration gains settings and notes. The body reads
  Note: '...' and Note { } beside the categories, and beside a body-level *.
parser\src\diagram-views.ts, name-resolver.ts, index.ts
  diagramViewNote(view): the body note, else the note setting.
  New code unknown-diagram-view-setting (error). A note or settings in a
  document without a version declaration: construct-requires-version.
parser\test\run-tests.ts
  Two checks: both note forms and precedence; the setting and version
  errors. 298 tests.
playground\src\components\inspector\selection.ts, ast-lookup.ts
  New selection kind 'diagram': the diagram on display.
playground\src\components\inspector\DiagramInspector.vue  (NEW)
  Main ERD: Project name and targets ("None declared" without a Project),
  counts of entities, database views, Containers, relationships and Edges,
  the diagram view names, the Project note, Edit in source. A diagram
  view: member counts and frames, categories as written, custom
  properties, note, Edit in source.
playground\src\components\inspector\Inspector.vue, App.vue
  The inspector shows DiagramInspector for the diagram selection, with
  the badge DIAGRAM or DIAGRAM VIEW; App passes the diagram view on
  display, which DiagramCanvas reports through diagram-view-change.
playground\src\components\diagram\DiagramCanvas.vue
  A click on the empty canvas selects the diagram instead of clearing the
  selection, so it no longer closes the inspector (the x button still
  does). The toolbar stays on one line: with the inspector open and the
  Diagram menu shown, "Reset positions" wrapped onto two lines.
playground\help\inspector-pane.md, diagram-views.md, diagram-pane.md,
diagnostics-panel.md, sixty-second-tour.md, your-first-schema.md,
visual-cues.md
  The diagram inspector, diagram view notes, the new code, and every
  sentence that said a background click deselects.
examples\16-diagram-views.xdbml
  Each diagram view has a note.
public\llms.txt, mcp\src\reference.ts (regenerated)
  The DiagramView row lists note and custom properties; the section's
  example has a body Note.
CHANGELOG.md
  v0.6.3: Spec entry for diagram view notes; parser, grammar, playground,
  llms.txt and example entries updated.

DECISION TO CONFIRM
  The empty-state proposal assumed the inspector stays open with nothing
  selected; it closes instead. So a background click now selects the
  diagram (a new selection kind), and closing the inspector is the x
  button only.
