xDBML -- VS Code extension 0.6.0
Base: origin/main 42d06ee (release 0.6.0).

The Marketplace has 0.3.0, whose grammar predates v0.4. This delta builds
0.6.0 and fixes one grammar gap found while checking it. It replaces the
0.4.0 delta: apply this one instead. If you already committed the 0.4.0
one locally, the APPLY steps below remove its .vsix.

VERSIONING
  From 0.6.0 the extension's major.minor follows the xDBML version its
  grammar covers; the patch number counts releases of the extension alone.
  0.4.0 and 0.5.0 are skipped (the Marketplace only needs each version to
  be higher than the last). Written into the extension CHANGELOG and
  PUBLISH.txt.

GRAMMAR FIX (site code blocks and the extension)
  The TextMate grammar colored `indexes`, `checks` and, since v0.6,
  `constraints` only as setting keys inside [ ], so the words that open
  those blocks in an entity body were never colored (the playground's
  Monaco editor did color them). New BLOCK_KEYWORDS list in
  parser\src\keywords.ts (indexes, checks, constraints, records) and a
  `block-keywords` pattern (scope keyword.other.block.xdbml) that matches
  them only before `{`, so a field named `constraints` stays uncolored.
  parser\src\keywords.ts, tools\textmate\xdbml.tmLanguage.template.json,
  scripts\build.mjs, xdbml.tmLanguage.json (regenerated), scripts\test.mjs
  (5 new checks). CHANGELOG.md: the v0.6 "Editor grammars" bullet was
  inaccurate on this point and now says what changed after 0.6.0.

WHAT THE 0.6.0 GRAMMAR ADDS OVER 0.3.0 (diffed against the old package)
  SupertypeGroup; setting keys supertype, completeness, exclusivity,
  strategy, merge, constraint_type, source_role, target_role, source_verb,
  target_verb; flag foreign_master; 72 target-native type names; block
  keywords indexes, checks, constraints, records.
