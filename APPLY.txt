Base: delta 3 (0.6.1, delta 3 of 5: renderer test and playground).

WHAT CHANGED
------------
public\llms.txt
  "How to author" gains three rules: one field or enum value per line with
  no separator (a parser ignores them; in indexes a comma is an error,
  write (a, b)); any keyword may name a field; settings go in the brackets
  after the name, never in the body. The View example states the
  placement before the code: settings in the brackets, then source_query
  once, the fields and an optional Note: in the body.
mcp\src\reference.ts            regenerated from llms.txt (check:reference
                                in sync).
mcp\test\run-tests.ts           5 tests (12 -> 17): commas validate; a
                                column named note validates; materialized
                                in a View body is a parse-error naming the
                                brackets; a bracketed source_query is a
                                warning; the reference carries the rules.
xDBML_in_5_minutes.md           one sentence on View setting placement
                                under the View example.
CHANGELOG.md                    v0.6.1 Tooling: MCP server and llms.txt.

API
  No change: the rendering API has no parser-facing code. The release
  script repoints it to @xdbml/render 0.6.1 and redeploys it.
