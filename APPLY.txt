xDBML -- 0.6.1, delta 2 of 5: grammar and parser
Base: origin/main 6b8f492 (0.6.1, delta 1: spec text).

The parser now reads what the 0.6.1 spec text says. Once pushed, the live
playground picks it up, since it builds the parser from source; the MCP
server and npm keep 0.6.0 until the release.

WHAT CHANGED
------------
parser\src\parser.ts
  Separators (3.9): commas and semicolons skipped between the items of every
    list body: Entity/Table, Edge, TablePartial, View, object-shaped Type,
    object, json, oneOf/anyOf/allOf, Enum, constraints, checks, Project
    (TableGroup and SupertypeGroup already did). A comma between index
    entries stays an error, now with a message pointing to (email, name).
  Keywords (3.10): Note starts a note only before ':' or '{'; indexes,
    checks, records only before '{' (constraints already did); source_query
    only before ':'. Otherwise the word names a field, as in DBML.
  Settings in a body: `materialized: true` in a View body fails with
    "'materialized:' is a setting: write it in the brackets after the View
    name, as in View monthly_revenue [materialized: ...] { ... }" instead
    of "Expected type name, got Colon". Same for Entity, Table, Edge and
    TablePartial bodies.
  Version (4): `xdbml: 0.6.1` parses (it failed on the dot).
    SUPPORTED_XDBML_VERSION is 0.6.1; 0.6 and 0.6.1 are accepted, 0.6.2 and
    0.7 refused as newer than supported.
parser\src\views.ts (NEW)
  viewSourceQuery(view): the first source_query: element of the body
    (28.7). checkViews(doc): warnings source-query-in-settings and
    duplicate-source-query (14.7), Views in Containers included.
parser\src\name-resolver.ts   the two codes; resolveNames() runs checkViews.
parser\src\index.ts           exports viewSourceQuery and checkViews.
parser\src\monarch.ts         playground editor: a field named `note` takes
                              the identifier color instead of bold keyword.
parser\test\run-tests.ts      18 new tests (241 -> 259).
grammar\xDBML.g4
  Header brought to v0.6.1. listSeparator in every list body; replacement
  rules tableDefinition, tablePartialDefinition, enumDefinition,
  tableGroupDefinition; fieldName with the six body keywords (tokens
  RECORDS and SOURCE_QUERY added); View: source_query a body element only,
  stale 17.12 references now 14.
grammar\test-cases.md         13 cases for 3.9, 3.10, 4 and 14, each run
                              against the parser here.
CHANGELOG.md                  v0.6.1: Added > Tooling, Fixed > Tooling.

DECISIONS WRITTEN INTO THE CODE -- please confirm
  1. `xdbml: 0.6.1` accepted; 0.6.2 refused (full version compared).
  2. The setting-in-body error also covers Entity, Table, Edge and
     TablePartial bodies. A field name is never followed by ':', so no
     valid input is rejected.
  3. The grammar is not compiled here: it imports the upstream DBML grammar,
     as before. The test cases were checked against the parser instead.
