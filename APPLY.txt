xDBML -- v0.5 Delta 8: llms.txt and MCP reference, editor grammars
Base: Deltas 1-7a applied and committed locally on top of origin/main fb985b1.

WHY
---
Fourth implementation phase: AI assistants (llms.txt and the MCP
xdbml_reference tool) and editors learn v0.5, so they write and highlight
supertype groups the way the spec defines them.

WHAT THIS CHANGES
-----------------
public\llms.txt (and mcp\src\reference.ts, regenerated from it)
  - every version line and example now says `xdbml: 0.5`
  - "supertype groups for generalization" joins the list of xDBML
    extensions to prefer
  - a new paragraph and example after entity-level relationships: when to
    write a SupertypeGroup, one group per axis, a required name, subtypes
    declaring only their own attributes (repeating one is an error),
    completeness and exclusivity (omit when unknown), a subtype in one
    group only, several levels; the materialization settings as derivation
    intent with a per-subtype strategy, discriminator not allowed on an
    overlapping group; point a relationship at a subtype by naming the
    subtype as an entity, not `Employee.party_id`
  The new example parses with no diagnostics under the v0.5 parser.

MCP tests
  - run against the parser source through the same test-only hook as the
    renderer and playground tests (mcp\test\parser-from-source*.mjs, wired
    into the `test` script); the deployed worker still bundles
    @xdbml/parse from its lockfile
  - three new cases: a group document is valid and counts 3 entities;
    subtype-in-multiple-groups and supertype-attribute-redeclared surface
    as diagnostics; `xdbml: 0.6` is refused

Editor grammars
  - parser\src\keywords.ts: supertype, completeness, exclusivity, strategy,
    merge join SETTING_KEYS (SupertypeGroup was added in Delta 4)
  - tools\textmate\xdbml.tmLanguage.json regenerated by its build script
  - tools\vscode-extension\syntaxes\xdbml.tmLanguage.json copied by the
    extension's prepare script. This copy had never picked up the v0.4
    keywords either, so foreign_master and constraint_type arrive with it.
  - no new .vsix is built; publishing the extension is your call

Remaining chapter-number references
  Nothing left to renumber. What is left citing chapters 12-30 is pinned
  to a version ("xDBML v0.2 §16.2", "v0.2 module system (spec §26)"), uses
  the grammar file's own §17.x numbering, or is new §12 text. The playground
  help page module-system.md waits for Delta 9 with the other help pages.
