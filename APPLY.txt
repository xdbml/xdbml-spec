HOW TO APPLY
------------
Extract this folder anywhere outside the repo and run:

    apply.cmd                      (repo at C:\Repos\Hackolade\xdbml-spec)
    apply.cmd D:\path\to\xdbml-spec

apply.cmd checks that the seven files are unchanged since b72912c, copies
them, runs npm ci in root, playground, renderer, mcp and api, runs npm audit
on the four lockfiles that had findings, then runs the gate (npm run check,
mcp check:reference and type-check, api type-check). It stops at the first
failure and does not commit. When it ends green it prints the three git
commands to commit and push.

The push triggers CI and deploy.yml, which rebuilds the site with npm ci
from the new lockfiles. GitHub closes each Dependabot alert on its own once
the patched lockfile is on main. The two Workers need no redeploy: see
"Workers" below.

DECISION TO CONFIRM: THE VITE OVERRIDE
--------------------------------------
The vite advisories cover every release up to 6.4.2. The 5.x line is no
longer patched (5.4.21 is its last release), and VitePress 1.6.4, the
latest stable, requires ^5.4.14. npm audit therefore reports "no fix
available" for vitepress. Three ways out:

  1. Override vite to 6.4.3 under VitePress 1.6.4.   <-- in this package
     VitePress declares ^5.4.14, so this runs outside its stated range.
     @vitejs/plugin-vue 5.2.x, which VitePress uses, lists vite 6 as
     supported. The built site has the same 316 files and 83 pages as
     the Vite 5 build, with identical text on the pages compared.
  2. Move to VitePress 2.0.0-alpha.20 (Vite 8). An alpha, with theme and
     config changes to review. A separate delta if you want it.
  3. Leave the root as is and dismiss the alerts as "dev server only".
     The vite and esbuild findings affect vitepress dev on a developer
     machine, several of them on Windows specifically.

Remove the override when the site moves to VitePress 2. If you prefer 2
or 3, drop package.json and package-lock.json from the commit: the other
five files stand on their own.
