xDBML -- 0.6.5, delta 1: spec text (internal definitions)
Base: origin/main 666eaba (dependency security update). Built 2026-10-03.

An entity may declare internal definitions, the named types a JSON Schema
document holds under $defs, in a definitions { } block (spec 15.8). This
delta is the spec text and the changelog. The parser does not read the
block yet: grammar and parser come in delta 2, so the new snippets get no
"View in playground" button until then.

HOW TO APPLY
------------
Extract this folder anywhere outside the repo and run, from cmd.exe in it:

    apply.cmd                      (repo at C:\Repos\Hackolade\xdbml-spec)
    apply.cmd D:\path\to\xdbml-spec

apply.cmd checks that 666eaba is in the history of HEAD and that the four
files are unchanged since 666eaba, copies them, and runs the gate
(npm run check). It stops at the first failure and does not commit. When it
ends green it prints the three git commands to commit and push. No package
or lockfile changes, so no npm install.

DECISIONS APPLIED (confirmed in chat, 2026-10-03)
-------------------------------------------------
  Keyword definitions, no $defs alias.
  Entry form: a Type declaration without the Type keyword.
  An entry under the name of a Type (or an Enum) otherwise visible to the
  entity takes precedence there and draws a warning.
  Error for relational targets, Cassandra, ScyllaDB, Neo4j, Memgraph,
  Neptune and JanusGraph; every other target accepts it, MongoDB included.
  UDTs stay project-level Types; no container-scoped Types.
  Entity bodies only, at most one block per body.
  TablePartial fields resolve where the TablePartial is declared.
  A field imported on its own takes the definition's shape inlined; a
  recursive definition makes that import an error.
  Point release 0.6.5; documents keep declaring xdbml: 0.6.
  No version-based warning tier: no parser read the block before 0.6.5.
