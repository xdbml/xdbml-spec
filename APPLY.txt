THE WHOLE DEPLOYMENT, IN TWO COMMANDS
-------------------------------------
From cmd.exe at the repo root (C:\Repos\Hackolade\xdbml-spec), on main:

  apply.cmd            branch, gate, commit this delivery, open the pull request
  apply.cmd release    merge the pull request, release 0.7.3, tag v0.7.3

Each step stops at the first failure, says what failed, and can be rerun
once the cause is fixed. Nothing is published before step 2.

Step 1 checks that the GitHub CLI is logged in and that main is level with
origin/main, then creates the branch dev/0.7.3, which takes the changes of
the working tree. On a rerun it finds itself on dev/0.7.3 and goes on from
there. It runs npm run check and the type-check of the MCP server, commits
every change in the tree except PR-0.7.3.md, pushes the branch, and opens
the pull request into main with PR-0.7.3.md as its description.

Step 2 waits for the checks of the pull request and merges it with
--admin, since the rules of main ask for a review that the author of the
pull request cannot give. It then switches to main and pulls, runs
tools\release-preflight.cmd 0.7.3, dates the CHANGELOG, and runs
tools\release.cmd 0.7.3: @xdbml/parse and @xdbml/render 0.7.3 on npm, the
MCP server and the rendering API deployed, "release 0.7.3" committed and
pushed, the tag v0.7.3 and its GitHub release from the "## v0.7.3" section
of the CHANGELOG. xdbml.org deploys from main.
